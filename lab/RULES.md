# 实验规则与 bot 协议 v1

## 信息与地形

世界仍为 H3 环形方格地图。船和己方 factory / dropoff 各提供 `VISION_RADIUS` 范围内的曼哈顿视野，玩家共享这些区域的并集。没有船时仍能看到基地附近。

每帧仅发送可见敌船与 dropoff，隐藏敌方银行及视野外资源。不会发送敌方全局船数。己方资产始终可见。初始 factory 位置、全图静态地形公开。动态资源的未知值为 `null`；先前见过的格子离开视野后重新为 `null`。bot 可自行维护过期的地图记忆。实验协议不向 bot 发送地图种子。

礁石不可通行、没有初始资源、不能建造。撞礁的移动作为停留处理，不消耗移动费用，并按普通停留采矿。礁石不挡视线。生成器把同一组礁石复制到所有玩家起始分区，保留 factory 曼哈顿半径 2 的水域，并逐组检查所有可航行格子是否连通。`REEF_PERCENT` 是候选概率；实际比例可能低于此值，范围 0 至 40。

当前测试器使用宽为 4 的倍数、高为 2 的倍数的地图，满足 2/4/8 人的原版分区约束。

## 回合顺序

1. 从回合开始状态向所有 bot 发送各自观测，收取动作。
2. 按 H3 原规则构建 dropoff。
3. 同时移动，扣除源格矿量除以移动费用比的整数部分。
4. 对每个目的格同时结算移动船和原地船的碰撞。
5. 己方结构上的船卸货。
6. 生成新船，结算生成位置的碰撞。
7. 未被本回合移动、卸货、出生或战斗更新的存活船采矿。
8. 沿用原版 inspiration / capture 及结束判定。

移动交叉互换位置不会碰撞。步骤 4 的重量是移动扣费后的载矿量。无论所有权，唯一最轻的船保留，抢走全部被击坠船的货物。若最轻重量并列，该格所有船沉没，全部货物变为地面矿，包括结构所在格。

同重特指最轻者并列。例如 `100, 300, 300` 由 100 存活；`100, 100, 300` 全灭。保留 H3 容量 1000，抢矿溢出的矿落地。战斗存活船不再在同回合额外采矿。步骤 6 同样采用该规则，但它在步骤 5 卸货之后，因此刚卸货的友军船可能与空载出生船同重沉没。

结构仍按 H3 规则存在，不引入 H4 的敌船摧毁 shipyard 机制。不增加资源再生。`INSPIRATION_ENABLED` 可用配置覆盖，默认保留 H3 的 true。`LIGHT_SHIP_COLLISIONS=false` 时沿用上游全灭及结构接收撞毁矿的行为。

## 输入

首行是完整 JSON 对象（以下省略了部分常量），bot 回复名称并 flush：

```json
{"type":"init","protocol":"halite3-lab-v1","player_id":0,"turn":0,"width":32,"height":32,"constants":{"MAX_TURNS":200,"VISION_RADIUS":4},"terrain":[0,0,1],"halite":[0,null,null],"players":[{"id":0,"factory":[0,0],"bank":5000,"ships":[],"dropoffs":[]}]}
```

随后每回合一行 `type=turn` 的 JSON，拥有同样的观测字段，但不重复发送 `constants` 与 `protocol`。`terrain` 和 `halite` 均为长度 `width*height` 的行优先数组，`index=y*width+x`；地形值 0 为海洋、1 为礁石。`players` 包含所有玩家的公开身份和 factory；敌方空 `ships` 列表仅表示当前没有可见敌船。

船对象：`{"id":3,"x":5,"y":7,"cargo":240}`。dropoff 用 `[x,y]`。己方 `bank` 为整数，启用迷雾时敌方为 `null`。坐标原点在左上方，north 减 y，east 加 x，所有方向取模。

## 输出

初始化回复任意一行名称。每回合回复一行 H3 动作字符串，必须 flush：

```text
m 3 n m 7 o g
```

- `m <ship-id> <n|s|e|w|o>`：移动或停留。
- `c <ship-id>`：按原版成本建造 dropoff。
- `g`：在 factory 生成一艘新船，每玩家每回合最多一次。
- 空行：所有船停留，不造船。

日志写到 stderr，stdout 只输出协议。可使用任意支持标准输入输出的语言。engine 初始化超时 30 秒，回合超时沿用原版设置；arena 另有整场超时。超时、bot 崩溃或协议错误产生失败尝试，最多重试指定次数。

## 注册

在配置的 `bots` 数组添加：

```json
{
  "name":"my-bot-v1",
  "command":["python3","bots/my_bot.py","--seed","123"],
  "sources":["bots/my_bot.py","bots/helpers.py"]
}
```

命令工作目录为项目根目录，`command` 通过逐参数 shell quoting 交给原版 engine 的进程启动器。每个模式中 bot 名称唯一，同一局不重复同一注册项。需要同策略自对弈时，用两个不同注册名称添加对应 bot。可执行文件、模型或策略数据也应加入 `sources`，它们的内容会被记录并在恢复时校验。

## 回放

保留 H3 replay 的逐帧结构，在地形格的 JSON 中增加 `reef: true`，顶层增加 `lab_replay_schema: halite3-lab-v1`。完整规则存于 `GAME_CONSTANTS`。`shipwreck` 碰撞事件只列出被摧毁船；存活者的位置、载矿在下一帧船状态中记录。回放与 match 目录中的启动参数、随机种子、座位、源文件摘要共同用于复核一局实验。

完整回放在比赛正常结束时写出。中断的尝试可能只有启动参数和日志；重试成功后产生完整回放。原版的 `final_snapshot` 缺少 bot 内部状态和完整回合上下文，不能作为本项目的逐回合恢复承诺。
